# Auto-Farm Key System\n\nEach auto-farm should have its own stable `farmId`, for example:\n\n- `blox-fruits`\n- `pet-sim`\n- `game-name`\n\nThe shared `KeyGate.lua` sends that `farmId` to the backend.\n\n## Flow\n\n1. User starts an auto-farm.\n2. The farm checks its key with `/api/verify`.\n3. If there is no valid key, the UI can direct the user to that farm's Linkvertise Target-Link.\n4. After Linkvertise completes its supported anti-bypass flow, the resulting hash is sent to `/api/unlock`.\n5. The backend verifies the hash with Linkvertise and creates a time-limited key bound to that farm (and optionally the Roblox user).\n6. The farm verifies the returned key and continues.\n\n## Important\n\nLinkvertise publisher credentials stay in the backend environment. Never put `LINKVERTISE_AUTH_TOKEN` or `ADMIN_TOKEN` in a Lua file or GitHub repository.\n\nThere is no safe GitHub-side mechanism that can magically inject executable key-gate code into arbitrary new Lua files without a convention. Use `_TEMPLATE.lua` for new farms, or have each farm call the shared `KeyGate` module.\n\nAlso, the backend must be deployed over HTTPS and Roblox HTTP requests must be allowed by the target environment.
